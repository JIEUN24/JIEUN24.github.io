# FE와 BE의 첫 협업

6주차를 마무리하며 프론트와 백의 첫 협업에 대해 되돌아보는 시간을 가졌다. 그 전까지는 프론트와 백을 나누지 않고 하나하나의 개인 프로젝트를 진행했다면 이제부턴 현업에서 필요한 의사소통 기술과 협업 기술을 배우기 위한 단계인 것 같다. 

처음으로 API 명세서를 같이 짜보고 그에 따라 서버와 데이터를 주고 받으며 프로젝트를 완성해나갔다. API 명세서를 보고 적는 것이 처음이라 헷갈리는 부분도 있었지만 이 부분을 정확하게 짚고 넘어가야 데이터를 주고 받을 때 문제가 생기지 않는다는 것을 알게 되었다. 

프론트와 백 서로 수정되는 부분이 있을 때는 미리 사전에 고지를 하고 그 부분을 맞춰나가기 위해 소통하였으며 그 결과 투두리스트 서비스를 구현할 수 있었다.

## 항해 99 6주차 미니프로젝트 과제

### 프로젝트 소개

해야할 일들을 TODO List로 등록하고 관리할 수 있게하는 간단한 TODO list 서비스. 타 유저와 공유 없이, 로그인한 본인의 목록만 확인하는 프라이빗한 투두리스트입니다!

#### Frontend(React)
- **최지은**: 로그인/회원가입/회원탈퇴 (user)
- **이경태**: TODO_LIST (main)

#### Backend(Spring)
- **송은혜**: 시큐리티&jwt / 사용자 정보 조회API / 회원 탈퇴API
- **박만수**: TODO 삭제,수정 API / 체크박스 (TODO완료체크) API
- **김호빈**: TODO 전체 조회, 등록 API

## 협업 과정에서 배운 점

### API 명세서의 중요성
이번 프로젝트에서 가장 중요했던 것은 API 명세서였다. 프론트엔드와 백엔드가 데이터를 주고받기 위해서는 명확한 규칙과 형식이 필요했고, 이를 문서화하는 과정에서 많은 것을 배웠다.

### 의사소통의 중요성
개발 과정에서 수정사항이나 변경사항이 생길 때마다 팀원들과 즉시 소통하는 것이 얼마나 중요한지 깨달았다. 사전에 고지하고 조율하는 과정이 있어야 프로젝트가 원활하게 진행될 수 있었다.

### 역할 분담과 책임
각자 맡은 역할에 대한 책임감을 가지고 진행하되, 다른 팀원의 작업에도 관심을 가지고 도움을 주고받는 것이 중요했다.

## 아쉬웠던 점과 개선방향

아직 협업에 익숙하지 않아 초기 설정이나 API 연동 과정에서 시행착오가 있었다. 다음 프로젝트에서는 더 체계적인 계획과 명확한 커뮤니케이션을 통해 효율성을 높여야겠다는 생각이 들었다.

또한 코드 리뷰나 Git 브랜치 전략 등 협업을 위한 기술적인 부분도 더 학습해야 할 필요성을 느꼈다.

## 소감

첫 협업 프로젝트를 통해 개발자로서 기술적인 역량뿐만 아니라 소통 능력의 중요성을 깨달았다. 혼자 개발할 때와는 완전히 다른 경험이었고, 현업에서 어떻게 일해야 하는지에 대한 감을 조금이나마 잡을 수 있었다.

비록 작은 프로젝트였지만 팀원들과 함께 하나의 서비스를 완성해냈다는 성취감이 컸다. 앞으로도 이런 협업 경험을 통해 더 나은 개발자로 성장해나가고 싶다.
